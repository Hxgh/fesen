# porthole

穿过一道自己开的舷窗，从外面看进内网。

## 它是什么

不是传统端口映射（frp / 花生壳那种「本地 3306 ↔ 公网 13306」的固定关系）。

porthole 是**按目标寻址的隧道**：隧道先建好，目标地址在每次连接时才决定。你在家里发起
「我要去 198.51.100.10:8080」，公司端 agent 拿这个目标跟「IP 段清单 + 端口范围清单」
比对，通过了才放行。

## 三个角色

| 目录 | 角色 | 跑在哪 |
|---|---|---|
| `apps/agent` | 出站代理，**ACL 在这里执行** | 公司内网机器 |
| `apps/relay` | 盲中继 + 信令 + 鉴权 | 公网服务器 |
| `apps/desk` | Tauri 桌面/移动客户端 | 家里 macOS / Windows / Android |

`packages/proto`（隧道协议）和 `packages/acl`（范围解析与匹配）被三方共用，
不重复实现。

## 为什么必须有服务端

1. 公司机器在 NAT 后，没有公网 IP，无法接受入站连接 —— 只能自己主动往外连。
2. 家里通常也在 NAT 后，两端需要双方都能到达的固定会合点。
3. 服务端还管设备注册、策略下发、在线状态、访问审计。

打洞优先、中继兜底。中继是兜底项，不能省。
